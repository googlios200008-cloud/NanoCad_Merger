# Приёмка NanoMerger на реальном EPLAN-комплекте

Автоматические тесты проверяют ядро на DXF. Они не доказывают совместимость с
вашей версией ODA, EPLAN, nanoCAD/AutoCAD и конкретными шрифтами/стилями печати.
Перед выдачей заказчику выполните этот короткий протокол на целевой машине.

## 1. Среда

- [ ] Windows/macOS/Linux целевой версии, Python 3.10+ (или собранный EXE).
- [ ] Установлен ODA File Converter; записаны версия и путь.
- [ ] `nanomerger doctor --require-oda --oda <путь>` завершился с кодом 0.
- [ ] Есть тестовая папка из 3–5 реальных файлов EPLAN: `Name1.dwg`, `Name2.dwg`, `Name10.dwg`.

## 2. Демо и реальный комплект

```bash
python examples/make_demo.py --dwg --oda <путь>
nanomerger scan <папка EPLAN>
nanomerger merge <папка EPLAN> -o <папка результата> --oda <путь> --json
```

- [ ] `nanomerger scan` показал ожидаемый числовой порядок.
- [ ] Созданы ровно три итоговых файла: DWG, PDF, `report.json`.
- [ ] В отчёте `status: complete`, число листов равно числу исходников.
- [ ] Повторный запуск без `--overwrite` не перезаписал комплект.

## 3. Проверка DWG в CAD заказчика

- [ ] DWG открывается без восстановления/критических ошибок.
- [ ] В пространстве модели чертежи идут слева направо без наложения, зазор соответствует настройке.
- [ ] Количество и порядок вкладок листов совпадают с отчётом.
- [ ] Каждый лист показывает только свой чертёж, бумага и ориентация верные.
- [ ] Рамки, провода, клеммы, символы, тексты, кириллица, размеры и штриховки на месте.
- [ ] Слои и блоки разных исходников не подменили друг друга.
- [ ] Единицы и физические размеры соответствуют исходному комплекту.

## 4. Проверка PDF

- [ ] Количество страниц равно количеству листов DWG.
- [ ] Порядок и размеры страниц совпадают с листами CAD.
- [ ] Геометрия читаема, нет обрезанных рамок/подписей.
- [ ] Отличия шрифтов/весов линий от native-печати CAD зафиксированы и согласованы.
- [ ] Если требуется точное совпадение с печатью CAD, текущий PDF не выдаётся как финальный без отдельного CAD-адаптера печати.

## 5. Негативные проверки

- [ ] Папка без DWG даёт понятную ошибку.
- [ ] `Name1.dwg` и `Name_001.dwg` вместе дают ошибку неоднозначного номера.
- [ ] Файл с XREF/proxy/неподдерживаемым объектом останавливает задание без частичного результата.
- [ ] Отмена во время конвертации останавливает дочерний процесс и не публикует неполный комплект.
- [ ] Закрытый/занятый файл результата даёт ошибку прав, прежний комплект сохраняется.

## Что делать при несовпадении

Сохраните `report.json`, версию ODA, версии CAD и обезличенный минимальный
исходный файл, на котором воспроизводится проблема. Не отправляйте секретные
производственные чертежи в публичные issue. Для точной печати следующий этап —
адаптер установленного CAD, который печатает созданные листы его собственным
движком с исходными CTB/STB и шрифтами.
